# SeedVR2 输出保留策略（成本资源治理 P0-1 / P1-1）

> 📅 2026-09-06 起生效 · 配置来源 `config.yaml` 的 `retention:` 段
> 评估报告缺陷 P1-1（清理范围与成品落点错位）与 P2（自动删除无说明）的整改文档。

## 1. 三层保留规则

| 规则 | 配置键 | 默认值 | 作用范围 | 行为 |
|---|---|---|---|---|
| 按年龄清理 | `retention.outputs_max_age_days` | 14 | `outputs/` | 修改时间早于阈值的文件周期性删除；`0` 禁用 |
| 按数量清理 | `retention.outputs_max_files` | 0（不限） | `outputs/` | 超过上限时从最旧文件开始删除；`0` 禁用 |
| 磁盘水位清理 | `retention.disk_min_free_gb` | 5.0 | **历史任务实际输出目录**（见 §2） | 剩余空间低于水位时，仅删除其中**超过 `outputs_max_age_days` 天**的旧文件，最旧优先，删到回到水位线为止 |

执行周期：`retention.outputs_cleanup_interval_seconds`（默认 3600 秒）；推理任务运行期间自动跳过，避免与活动任务写入竞争。

## 2. 清理范围与你的成品落点（重要）

- **`outputs/` 树**：始终受时间/数量规则管辖。长视频临时帧目录（`_frames`）也在范围内，失败残留会被回收。
- **任务实际输出目录**：默认输出模板 `user_preferences.output_path_template = '{input_dir}/restored/{input_name}{ext}'` 会把**成品写在输入文件旁边**（如 `data/uploads/restored/`），**不在 `outputs/` 内**，因此不会按时间自动删除。只有当磁盘剩余空间低于 `disk_min_free_gb` 水位时，才会对这些目录做超龄清理。
- 水位清理的目录列表来自历史库中最近任务的输出文件父目录（`HistoryDB.distinct_output_dirs`），只删文件、不删目录本身、`.gitkeep` 等占位文件永不清理、绝不删除未超龄的新文件。

## 3. 删除前通知

水位清理触发删除前，会经全局 SSE 通道（`/api/sse/events`）广播 `system_notice` 事件（含目录、当前剩余空间、水位阈值、候选文件数），前端页面会以警告 Toast 展示。也就是说：**你会在清理发生前看到提示**。

## 4. 如何调整 / 禁用

```yaml
retention:
  disk_min_free_gb: 5.0              # 水位阈值；0 = 禁用水位清理
  outputs_cleanup_interval_seconds: 3600
  outputs_max_age_days: 14           # 0 = 禁用 outputs/ 时间清理（同时水位清理失去受害者圈定规则，一并失效）
  outputs_max_files: 0               # 0 = 不限数量
```

建议：

- 想长期保留修复结果：把成品模板指向 `outputs/` 之外（默认即是），并保持 `outputs_max_age_days` 不变——成品目录只在磁盘紧张时按超龄回收；
- 担心磁盘写满：保留默认水位 5.0GB，它比时间规则更能防「长视频帧落盘阶段写满磁盘」；
- 完全不想要任何自动清理：三个键全部置 0。

## 5. 任务启动前的磁盘预检

除周期清理外，任务提交与批量编排启动时会做磁盘预检（`ensure_disk_space`，`retention.disk_min_free_gb` 同一阈值）：剩余空间不足直接拒绝新任务（HTTP 507 `INSUFFICIENT_DISK`），不会带着账目残缺进入执行。
