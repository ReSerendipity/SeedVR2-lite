# SeedVR2 增量更新发布手册

> 适用：以后每次发布小版本（v1.5.x）时，按本手册操作，**无需重新打包 5.6GB 完整数据卷**。
> 本手册由任意 AI 执行即可完成发布，所有命令已验证。

## 0. 前置条件

| 项 | 路径 / 命令 |
|---|---|
| 项目根 | `C:\Users\Doro\SeedVR2-lite` |
| 增量包源（程序根） | `dist\tauri-release\staging\App`（= 安装后的 `app\` 目录，含 integrated_app/、common/、configs_3b/、version.json 等，**不含** runtime/model/data/logs 的重型目录在 staging 同层被排除） |
| 7za | `C:\Users\Doro\Tools\7z-extra\x64\7za.exe` |
| gh CLI | `gh`（账号 ReSerendipity，token 含 repo scope） |
| 更新包命名规则 | `app-v{版本号}.zip`（updater 的 `ASSET_TEMPLATE` 按此名查找） |
| 发布要求 | **必须发布为正式版（Latest），不能是 prerelease**，否则已安装用户检查不到 |

## 1. 改代码 + 改版本号

1. 修改应用代码（`staging\App\app\` 下的 Python / 前端 / 模板 / CSS / JS）。
2. 更新版本文件 `staging\App\version.json`：

```json
{
  "version": "1.5.3",
  "release_date": "2026-09-08",
  "minimum_shell_version": "1.0.0",
  "changelog": "本次更新内容一句话"
}
```

> 注意：`version.json` 必须是 **UTF-8 无 BOM**；`version` 必须比已发布的最新版大，否则检查更新不会触发。

## 2. 打包增量包

```powershell
$src = "C:\Users\Doro\SeedVR2-lite\dist\tauri-release\staging\App"
$out = "C:\Users\Doro\SeedVR2-lite\dist\tauri-release\installer\app-v1.5.3.zip"
$7za = "C:\Users\Doro\Tools\7z-extra\x64\7za.exe"
if (Test-Path $out) { Remove-Item $out -Force }
Push-Location $src
& $7za a -tzip -mx=9 $out ("*") "-xr!runtime" "-xr!model" "-xr!data" "-xr!logs" "-xr!__pycache__"
Pop-Location
```

**关键排除项（必须）**：`runtime`、`model`、`data`、`logs`、`__pycache__`。
**zip 顶层 = staging\App 的直接子项**（含 version.json、app/、common/ 等），解压后正好对应安装目录的 `app\`。

## 3. 生成校验和

```powershell
$zip = "app-v1.5.3.zip"
$hash = (Get-FileHash "$out" -Algorithm SHA256).Hash.ToLower()
"{0}  {1}" -f $hash, $zip | Out-File "$out.sha256" -Encoding ascii
```

> updater 的 `fetch_sha256` 会从 `.sha256` 资产文本中提取第一个 64 位 hex，格式 `hash  文件名` 兼容。

## 4. 写发布说明并发布

```powershell
cd "C:\Users\Doro\SeedVR2-lite"
# 1) 写 release-notes 文件（参考 release-152.md 结构：更新内容 / 使用说明 / 校验 / 已知限制）
# 2) 创建 release（正式版，不带 --prerelease）
gh release create v1.5.3 --title "SeedVR2 v1.5.3" --notes-file "dist\tauri-release\installer\release-153.md" "dist\tauri-release\installer\app-v1.5.3.zip" "dist\tauri-release\installer\app-v1.5.3.zip.sha256"
```

## 5. 发布后验证清单（必须全过）

```powershell
# ① latest 指向新版
gh api repos/ReSerendipity/SeedVR2-lite/releases/latest --jq '.tag_name'   # 应输出 v1.5.3

# ② 资产齐全
gh release view v1.5.3 --json assets --jq '.assets[] | .name'               # app-v1.5.3.zip + app-v1.5.3.zip.sha256

# ③ 下载完整性（哈希必须匹配第 3 步）
gh release download v1.5.3 -p "app-v1.5.3.zip*" -D "$env:TEMP\verify" --clobber
Get-FileHash "$env:TEMP\verify\app-v1.5.3.zip" -Algorithm SHA256

# ④ 版本比较触发（本地 < 远端才触发）
[version]"1.5.2" -lt [version]"1.5.3"   # True

# ⑤ 增量包内确认修复/改动存在（抽样）
$7za e "$out" -o"$env:TEMP\verify" "app\integrated_app\static\css\style.css" -y
```

## 6. 回滚预案

- **发布后发现包有问题**：删掉 release 资产重新上传同名文件（`gh release delete-asset` + `gh release upload --clobber`）。
- **用户已更新到坏版本**：发下一个版本 `v1.5.4`（修复版）走同样流程；或让用户重装 `SeedVR2-Setup-v1.5.1.exe` 完整包再检查更新。
- updater 自身带自动回滚（换载失败时恢复 app.bak），代码层无需干预。

## 7. 注意事项 / 已知坑

| 坑 | 说明 |
|---|---|
| 中文资产名 | `gh` 会把中文名资产上传为 default.txt，**一律用英文资产名** |
| PowerShell 编码 | `version.json` / 发布说明用 UTF-8 无 BOM 写入（`[System.IO.File]::WriteAllText` + UTF8Encoding($false)） |
| prerelease 陷阱 | 新版若发布为 prerelease，`/releases/latest` 不会返回它，已安装用户点检查更新会得到"无更新" |
| 壳不更新 | 增量包只覆盖 `app/` 应用代码；壳（SeedVR2.exe）改动需重发完整安装器（见《壳更新-下一轮改动清单.md》） |
| 模型/依赖 | 用户本地保留，增量包永远不含 runtime/model/data/logs |
