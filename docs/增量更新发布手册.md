# SeedVR2 增量更新发布手册

> 适用：以后每次发布小版本（v1.5.x）时，按本手册操作，**无需重新打包 5.6GB 完整数据卷**。
> 本手册由任意 AI 执行即可完成发布，所有命令已验证。

## 0. 前置条件

| 项 | 路径 / 命令 |
|---|---|
| 项目根 | `C:\Users\Doro\SeedVR2-lite` |
| 增量包源（程序根） | `dist\tauri-release\staging\App`（= 安装后的 `app\` 目录，含 integrated_app/、common/、configs_3b/、version.json 等，**不含** runtime/model/data/logs 的重型目录在 staging 同层被排除） |
| 7za | `C:\Users\Doro\Tools\7z-extra\x64\7za.exe` |
| gh CLI | `gh`（账号 ReSerendipity，token 含 repo scope） |
| 更新包命名规则 | `app-v{版本号}.zip`（updater 的 `ASSET_TEMPLATE` 按此名查找） |
| 发布要求 | **必须发布为正式版（Latest），不能是 prerelease**，否则已安装用户检查不到 |

## 1. 改代码 + 改版本号

1. 修改应用代码（`staging\App\app\` 下的 Python / 前端 / 模板 / CSS / JS）。
   - **同步方式（推荐）**：按 `git ls-files` 清单把仓库文件复制进 `staging\App` 对应位置——天然排除
     `runtime/model/data/logs/__pycache__`，以及被 gitignore 的 `app\ffmpeg.exe`、`app\ffprobe.exe`（各 221MB）。
     覆盖前先把 staging 被覆盖的文件备份到 `dist\tauri-release\_backup\`。
   - **⚠️ 若本次改动落在核心安全模块**（`app_server.py` / `config.py` / `model_manager.py` / `security/*` /
     `middleware\{csrf,basic_auth,rate_limit}.py` / `engines\seedvr2_engine.py`），**必须重生成并重签完整性清单**
     （见 §8），否则发布版启动自检 11 项中会有一项失败。
2. 更新版本文件 `staging\App\version.json`：

```json
{
  "version": "1.5.3",
  "release_date": "2026-09-08",
  "minimum_shell_version": "1.0.0",
  "changelog": "本次更新内容一句话"
}
```

> 注意：`version.json` 必须是 **UTF-8 无 BOM**；`version` 必须比已发布的最新版大，否则检查更新不会触发。

## 2. 打包增量包

```powershell
$src = "C:\Users\Doro\SeedVR2-lite\dist\tauri-release\staging\App"
$out = "C:\Users\Doro\SeedVR2-lite\dist\tauri-release\installer\app-v1.5.3.zip"
$7za = "C:\Users\Doro\Tools\7z-extra\x64\7za.exe"
if (Test-Path $out) { Remove-Item $out -Force }
Push-Location $src
& $7za a -tzip -mx=9 $out ("*") "-xr!runtime" "-xr!model" "-xr!data" "-xr!logs" "-xr!__pycache__"
Pop-Location
```

**关键排除项（必须）**：`runtime`、`model`、`data`、`logs`、`__pycache__`。
**zip 顶层 = staging\App 的直接子项**（含 version.json、app/、common/ 等），解压后正好对应安装目录的 `app\`。

## 3. 生成校验和

```powershell
$zip = "app-v1.5.3.zip"
$hash = (Get-FileHash "$out" -Algorithm SHA256).Hash.ToLower()
"{0}  {1}" -f $hash, $zip | Out-File "$out.sha256" -Encoding ascii
```

> updater 的 `fetch_sha256` 会从 `.sha256` 资产文本中提取第一个 64 位 hex，格式 `hash  文件名` 兼容。

## 4. 写发布说明并发布

```powershell
cd "C:\Users\Doro\SeedVR2-lite"
# 1) 写 release-notes 文件（参考 release-152.md 结构：更新内容 / 使用说明 / 校验 / 已知限制）
# 2) 创建 release（正式版，不带 --prerelease）
gh release create v1.5.3 --title "SeedVR2 v1.5.3" --notes-file "dist\tauri-release\installer\release-153.md" "dist\tauri-release\installer\app-v1.5.3.zip" "dist\tauri-release\installer\app-v1.5.3.zip.sha256"
```

## 5. 发布后验证清单（必须全过）

```powershell
# ① latest 指向新版
gh api repos/ReSerendipity/SeedVR2-lite/releases/latest --jq '.tag_name'   # 应输出 v1.5.3

# ② 资产齐全
gh release view v1.5.3 --json assets --jq '.assets[] | .name'               # app-v1.5.3.zip + app-v1.5.3.zip.sha256

# ③ 下载完整性（哈希必须匹配第 3 步）
gh release download v1.5.3 -p "app-v1.5.3.zip*" -D "$env:TEMP\verify" --clobber
Get-FileHash "$env:TEMP\verify\app-v1.5.3.zip" -Algorithm SHA256

# ④ 版本比较触发（本地 < 远端才触发）
[version]"1.5.2" -lt [version]"1.5.3"   # True

# ⑤ 增量包内确认修复/改动存在（抽样）
$7za e "$out" -o"$env:TEMP\verify" "app\integrated_app\static\css\style.css" -y

# ⑥ 资产构成检查：Release 里必须只有增量包，绝不能出现 SeedVR2-Portable-*
gh release view v1.5.7 --json assets --jq '[.assets[].name]'    # 期望：app-v1.5.7.zip + app-v1.5.7.zip.sha256

# ⑦ 没有 Portable Release 运行在排队/进行中
gh run list --limit 5 --json workflowName,event,status --jq '.[]|select(.workflowName=="Portable Release")'
#   有的话：gh run cancel <id>（构建完成前取消不会上传任何资产），然后再复核 ⑥
```

> **⑥⑦ 是 2026-09-10 新增的必做项**：`gh release create` 会创建并推送 tag，从而触发 `portable-release.yml`。
> 该工作流现已在 tag 推送下**只构建、不发布**（提交 `c8d5576`，GOTCHAS #113），但**在此修复之前的版本会**
> `gh release edit` 覆盖你的发布说明并追加上传约 5.6GB 便携分卷——v1.5.6「误发成便携包」即由此产生。
> 每次发布后都要跑 ⑥⑦ 兜底。

## 6. 回滚预案

- **发布后发现包有问题**：删掉 release 资产重新上传同名文件（`gh release delete-asset` + `gh release upload --clobber`）。
- **用户已更新到坏版本**：发下一个版本 `v1.5.4`（修复版）走同样流程；或让用户重装 `SeedVR2-Setup-v1.5.1.exe` 完整包再检查更新。
- updater 自身带自动回滚（换载失败时恢复 app.bak），代码层无需干预。

## 7. 注意事项 / 已知坑

| 坑 | 说明 |
|---|---|
| 中文资产名 | `gh` 会把中文名资产上传为 default.txt，**一律用英文资产名** |
| PowerShell 编码 | `version.json` / 发布说明用 UTF-8 无 BOM 写入（`[System.IO.File]::WriteAllText` + UTF8Encoding($false)） |
| prerelease 陷阱 | 新版若发布为 prerelease，`/releases/latest` 不会返回它，已安装用户点检查更新会得到"无更新" |
| 壳不更新 | 增量包只覆盖 `app/` 应用代码；壳（SeedVR2.exe）改动需重发完整安装器（见《壳更新-下一轮改动清单.md》） |
| 模型/依赖 | 用户本地保留，增量包永远不含 runtime/model/data/logs |
| **`gh release create` 会触发便携构建** | 它创建并推送 tag → 触发 `portable-release.yml`（event=push）。该工作流自 `c8d5576` 起在 tag 推送下只构建不发布，但**发布后仍要跑 §5 ⑥⑦ 兜底**，必要时 `gh run cancel <id>` |
| **pre-push 钩子误报 FAIL** | 本机钩子在 `.venv` 子进程里找不到 git/python，`ruff`/`black`/`mypy`/API 契约会**全项误报失败**。用 `git push --no-verify`（DCO 由 `git commit -s` 保证），推送后独立复核 |
| **`gh` 必须在仓库目录内运行** | 否则报 `failed to run git: fatal: not a git repository`；用脚本调 gh 时需设 `cwd=<repo>` |
| **沙箱/受限环境下 git ref 写不落地** | 若 `git fetch` / `git update-ref` 后 ref 未变，以 `git ls-remote origin refs/heads/main` 为权威判断本地与远程是否一致 |
| **完整性清单过期** | 定版提交改了核心模块却没重签清单 → 发布版启动自检单模块失败（GOTCHAS #114）。发布前务必执行 §8 |

## 8. 核心安全模块改动后：重生成 + 重签完整性清单（必做）

只要本次改动落在清单覆盖的 11 个模块内（`app_server.py` / `config.py` / `model_manager.py` /
`security\*` / `middleware\{csrf,basic_auth,rate_limit}.py` / `engines\seedvr2_engine.py`），
发布前就必须重签，否则用户端启动自检会报 `[SECURITY] ⚠️ 核心模块完整性自检失败`
并写 `INTEGRITY_FAILURE` 审计事件（`enforce=true` 时直接拒绝启动）。

**关键约束**：签名对象必须是**仓库态字节**——`.gitattributes` 把 `*.json` 归一为 LF，而生成脚本写出的是 CRLF；
两者不一致时提交后验签会失败（GOTCHAS #103）。

```powershell
cd C:\Users\Doro\SeedVR2-lite
$M = 'app/integrated_app/security/integrity_manifest.json'

# ① 生成（此刻工作区是 CRLF，稍后会被仓库态字节覆盖）
.venv\Scripts\python.exe scripts\generate_integrity_manifest.py

# ② 入索引（.gitattributes eol=lf → 索引里归一为 LF）
git add $M

# ③ 用仓库态字节覆写工作区（二进制安全）
#    ⚠️ 不要用 `git checkout -- $M`：实测 git 会认为工作区「归一化后与索引一致」而静默跳过重写，
#    行尾仍是 CRLF，签名随即失效。必须显式用 git show 的原始字节覆写。
@'
import subprocess, pathlib
p = "app/integrated_app/security/integrity_manifest.json"
pathlib.Path(p).write_bytes(subprocess.run(["git", "show", ":" + p], capture_output=True).stdout)
'@ | Set-Content -Encoding UTF8 "$env:TEMP\norm_manifest.py"
.venv\Scripts\python.exe "$env:TEMP\norm_manifest.py"

# ④ 以仓库态字节签名
.venv\Scripts\python.exe scripts\sign_integrity_manifest.py
git add "$M.sig.ed25519"

# ⑤ 校验
.venv\Scripts\python.exe scripts\sign_integrity_manifest.py --verify     # 期望 [PASS]

# ⑥ 提交，然后**再复跑一次 ⑤**（换行归一化最容易在这里翻车）
git commit -s --no-verify -m "fix(security): 重生成并重签完整性清单"
.venv\Scripts\python.exe scripts\sign_integrity_manifest.py --verify     # 期望仍 [PASS]
```

最后把清单与签名同步进 staging，并在 staging 上实跑一次启动自检：

```powershell
Copy-Item $M dist\tauri-release\staging\App\app\integrated_app\security\ -Force
Copy-Item "$M.sig.ed25519" dist\tauri-release\staging\App\app\integrated_app\security\ -Force
# 期望：{"total": 11, "passed": 11, "failed": 0, "manifest_signed": true}
```
