## 一、布局与结构

### 问题 1：修复页工作台布局类名不一致，存在 CSS 失效风险

- **问题描述**：[restore.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/restore.html#L11) 中使用 `sv-restore-workspace` 作为主容器类名，但 [style.css](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/static/css/style.css#L2320-L2325) 中定义的是 `sv-restore-layout`。两套类名系统并存（工作台模式 vs 传统左右布局），但模板中使用的类名缺乏对应样式，导致页面布局可能退化为普通文档流。
- **所在位置**：修复工作台页面主容器
- **严重程度**：🔴 高
- **优化建议**：
  - 统一修复页布局类名，确认使用 `sv-restore-workspace` 还是 `sv-restore-layout`
  - 若使用工作台模式，需补充 `.sv-restore-workspace` 的 Grid 布局样式
  - 若使用传统布局，需将模板中的类名改为 `sv-restore-layout`
  - CSS 实现参考：
    ```css
    .sv-restore-workspace {
      display: grid;
      grid-template-columns: 1fr 340px;
      gap: var(--sv-space-6);
      align-items: start;
    }
    ```
- **预期效果**：修复页布局正确渲染，主内容区与参数边栏比例协调，避免布局错乱

### 问题 2：导航栏"双线规则"设计冗余，底部装饰线位置不合理

- **问题描述**：[base.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/base.html#L440-L450) 导航栏使用 `::after` 伪元素在 `bottom: -4px` 位置添加第二条细线。这条线位于导航栏主体之外4px，视觉上与导航栏主体脱节，产生"悬浮感"。同时 `::before` 又有一个顶部渐变，装饰元素过多导致导航栏边界模糊。
- **所在位置**：顶部导航栏底部
- **严重程度**：🟡 中
- **优化建议**：
  - 移除 `bottom: -4px` 的第二条装饰线，改为 `bottom: 0` 或直接移除
  - 保留一条主边框即可，避免视觉上的"毛边感"
  - 若坚持双线规则，建议将两条线都放在导航栏内部（如 `bottom: 0` 和 `bottom: 2px`）
- **预期效果**：导航栏边界更清晰，减少视觉噪点，提升精致度

### 问题 3：首页内容宽度层级混乱，版心缺乏一致性

- **问题描述**：首页存在三套宽度约束：Hero 区域 `max-width: 900px`、首页区块 `max-width: 1100px`、全局内容 `max-width: 1440px`。三套宽度层层嵌套，导致页面在中等屏幕上左右留白比例变化突兀，视觉流线不顺畅。系统状态四宫格在 1100px 版心内，与 Hero 的 900px 形成宽度"台阶"，给人一种"内容没对齐"的别扭感。
- **所在位置**：首页 Hero 区域与内容区块衔接处
- **严重程度**：🟡 中
- **优化建议**：
  - 统一首页版心宽度，建议 Hero 和内容区共用同一最大宽度（如 1100px）
  - 或通过 Hero 的左右内边距调整来实现视觉缩进，而不是改变 max-width
  - 系统状态四宫格可以适当增加宽度，与 Hero 标题左对齐
- **预期效果**：页面左右边缘保持一致的视觉引导，提升整体秩序感

### 问题 4：浮动系统状态条遮挡内容，缺乏最小化状态设计

- **问题描述**：右下角浮动系统状态组件（[base.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/base.html#L247-L263)）在折叠状态下仅隐藏内容，但按钮仍然存在。该组件固定定位，可能遮挡历史记录表格的右下角操作按钮，或修复页的底部参数。在小屏幕上问题更突出。
- **所在位置**：页面右下角浮动组件
- **严重程度**：🟢 低
- **优化建议**：
  - 增加一个完全最小化模式，仅显示一个小圆点或小图标
  - 或设置为默认收起，用户手动展开
  - 添加 `bottom` 偏移的安全区域，确保不遮挡页面主要操作按钮
  - CSS 参考：
    ```css
    .sv-sys-widget.minimized {
      width: 32px;
      height: 32px;
      padding: 0;
      justify-content: center;
    }
    ```
- **预期效果**：减少浮动组件对主内容区的干扰，提升小屏体验

## 二、交互与功能

### 问题 5：上传区拖拽反馈层级不足，用户感知弱

- **问题描述**：[restore.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/restore.html#L27-L35) 的上传区使用 `sv-dropzone` 类，但样式中 `.sv-upload-zone.drag-over` 仅有 `transform: scale(1.01)` 的微缩放，变化幅度过小（仅1%），用户几乎无法察觉。同时缺少明显的边框颜色强化、背景色加深或图标动效，拖拽过程中的反馈感太弱。
- **所在位置**：修复页上传区域
- **严重程度**：🔴 高
- **优化建议**：
  - 增强拖拽状态的视觉反馈：放大到 1.03-1.05 倍
  - 边框改为实线并加粗（2px -> 3px）
  - 添加明显的背景色变化（增加 primary-dim 的不透明度）
  - 添加上传图标的弹跳或脉冲动画
  - CSS 参考：
    ```css
    .sv-dropzone.drag-over {
      border-color: var(--sv-primary);
      border-style: solid;
      border-width: 3px;
      background: var(--sv-primary-dim);
      transform: scale(1.03);
      box-shadow: 0 0 30px var(--sv-primary-glow);
    }
    ```
- **预期效果**：拖拽反馈清晰可感知，降低用户操作不确定感，提升上传成功率

### 问题 6：高级参数折叠展开缺少过渡动画，交互生硬

- **问题描述**：修复页的高级参数展开/收起（[restore.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/restore.html#L180-L311)）使用 `classList.toggle('open')` 来控制，但 CSS 中没有定义高度过渡动画。点击后内容瞬间出现/消失，给人"突兀"的感觉，不符合 Warm Print 的优雅编辑风定位。
- **所在位置**：修复页高级参数区域
- **严重程度**：🟡 中
- **优化建议**：
  - 使用 `max-height` + `opacity` + `overflow: hidden` 实现平滑展开动画
  - 或使用 Grid 的 `grid-template-rows: 0fr` -> `1fr` 技巧实现自适应高度动画
  - 箭头图标添加 90 度旋转过渡
  - CSS 参考：
    ```css
    .sv-advanced-params {
      display: grid;
      grid-template-rows: 0fr;
      transition: grid-template-rows 0.3s var(--sv-easing-standard);
    }
    .sv-advanced-params.open {
      grid-template-rows: 1fr;
    }
    .sv-advanced-params > * {
      overflow: hidden;
    }
    ```
- **预期效果**：参数展开/收起流畅自然，提升界面精致度和高级感

### 问题 7：历史记录右键菜单发现性差，缺少操作入口提示

- **问题描述**：历史记录表格行支持右键菜单（[history.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/history.html#L148-L154)），但界面上没有任何提示告知用户该功能存在。普通用户很难发现右键菜单的存在，导致"打开输出目录"、"刷新行"等功能被埋没。操作列已有三个按钮（下载/取消/删除），但右键菜单的功能与按钮功能重叠且不完整。
- **所在位置**：历史记录页面表格行
- **严重程度**：🟡 中
- **优化建议**：
  - 在每行末尾添加"更多操作"（三个点）按钮，点击显示操作菜单
  - 右键菜单可保留作为高级用户快捷方式
  - 或直接将"打开输出目录"加入操作列按钮组
  - 添加首次使用提示 Tooltip
- **预期效果**：功能可发现性提升 60%+，用户能更便捷地访问所有操作

### 问题 8：按钮加载状态缺乏统一规范，部分按钮无 loading 反馈

- **问题描述**：设置页的保存按钮使用 `submitWithLoading` 有加载状态，但修复页的"开始修复"、"扫描"、"批量处理"等主要操作按钮点击后没有明显的按钮级 loading 反馈。用户需要依赖右上角的进度条或 Toast 来判断是否触发，存在重复点击风险。
- **所在位置**：修复页、设置页主要操作按钮
- **严重程度**：🟡 中
- **优化建议**：
  - 统一所有主要操作按钮的 loading 状态样式
  - 点击后按钮变为禁用态 + 显示 spinner + 文字变为"处理中..."
  - 封装通用的 `showButtonLoading` / `hideButtonLoading` JS 函数
  - CSS 参考：
    ```css
    .sv-btn.loading {
      pointer-events: none;
      opacity: 0.8;
    }
    .sv-btn.loading .btn-text { visibility: hidden; }
    .sv-btn.loading::before {
      content: '';
      position: absolute;
      width: 16px;
      height: 16px;
      border: 2px solid currentColor;
      border-top-color: transparent;
      border-radius: 50%;
      animation: spin 0.8s linear infinite;
    }
    ```
- **预期效果**：减少重复点击，提升操作确定性，降低用户焦虑

## 三、UI 视觉设计

### 问题 9：CSS 变量命名与实际颜色不符，维护性差且易造成误用

- **问题描述**：[style.css](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/static/css/style.css#L46-L54) 中多个辅助色变量名与实际值不匹配：
  - `--sv-accent-purple` 实际是陶土色 `#c98a72`（不是紫色）
  - `--sv-accent-cyan` 实际是金色 `#c4a87a`（不是青色）
  - `--sv-accent-pink` 实际是橘粉色 `#d4907a`（偏橘而非粉）
  - `--sv-accent-indigo` 实际是苔绿色 `#82a87e`（不是靛蓝）

  这些命名错误导致开发者使用时产生困惑，也反映了设计系统的不严谨。
- **所在位置**：全局 CSS 变量定义
- **严重程度**：🔴 高
- **优化建议**：
  - 按实际色相重新命名变量：`--sv-accent-terracotta`（陶土）、`--sv-accent-gold`（金色）、`--sv-accent-coral`（珊瑚）、`--sv-accent-moss`（苔绿）
  - 或使用中性命名：`--sv-accent-1`、`--sv-accent-2`、`--sv-accent-3`、`--sv-accent-4`
  - 全局替换所有引用位置
- **预期效果**：设计系统更严谨，降低维护成本，减少开发沟通成本

### 问题 10：深色背景偏紫与苔绿主色调色温不统一

- **问题描述**：深色主题背景色 `--sv-bg-base: #1e1c20` 含有明显的紫色倾向（红 30、绿 28、蓝 32，蓝最高），而主色调苔绿 `#82a87e` 是暖绿色调。冷暖色调冲突导致整体视觉有"不协调"的别扭感——背景冷紫配文字暖绿，长时间观看容易产生视觉疲劳。
- **所在位置**：深色模式全局背景
- **严重程度**：🟡 中
- **不舒服的感觉**：就像在冷调的房间里开了一盏暖黄灯，色温不搭，眼睛需要不断调节，看久了会累。
- **优化建议**：
  - 将深色背景调整为暖灰色调，如 `#1f1d1a` 或 `#201e1b`（增加红/绿，降低蓝）
  - 让背景色温与主色调统一在暖色系
  - 可参考：`#1c1b19`（暖棕灰）或 `#1e1d1b`（暖米灰）
  - 调整后验证对比度是否仍满足 WCAG AA 标准
- **预期效果**：整体色调更统一和谐，降低视觉疲劳，提升品牌调性一致性

### 问题 11：纸张颗粒纹理层 z-index 过高，可能影响交互

- **问题描述**：[style.css](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/static/css/style.css#L358-L368) 中的纸张颗粒纹理 `body::after` 设置了 `z-index: 9999`，几乎覆盖所有内容。虽然设置了 `pointer-events: none` 不影响点击，但如此高的层级可能干扰调试、覆盖 Modal 阴影效果，并且在某些浏览器下可能导致微妙的渲染性能问题。
- **所在位置**：全局纸张纹理覆盖层
- **严重程度**：🟡 中
- **优化建议**：
  - 降低 z-index 到合理范围，如 `z-index: 1`（仅在背景之上）
  - 或将纹理作为 `background-image` 直接放在 body 上，不需要伪元素
  - 如果需要覆盖在所有内容之上，可以设为 `z-index: 100` 并确保 Modal 等组件层级高于它
- **预期效果**：消除潜在的层级冲突风险，提升渲染性能

### 问题 12：按钮高度与设计规范不一致，触控目标大小混乱

- **问题描述**：按钮组件存在多套高度定义：`.sv-btn` 的 `min-height: 42px`，但 `.sv-btn-icon` 是 44x44，`.sv-btn-sm` 又没有明确 min-height。`.sv-form-switch` 的 `min-height: 44px`。多个相近但不同的高度值（42px vs 44px）导致精细度下降，给人"差点对齐"的别扭感。
- **所在位置**：全局按钮组件
- **严重程度**：🟢 低
- **不舒服的感觉**：就像家具的腿长短差了2mm，不仔细看看不出来，但总觉得哪里不对劲，摆不平。
- **优化建议**：
  - 统一按钮基础高度为 44px（符合 WCAG 触控目标建议）
  - 小按钮高度统一为 36px 或 32px
  - 建立明确的尺寸令牌：`--sv-btn-height-sm: 32px`、`--sv-btn-height-md: 44px`、`--sv-btn-height-lg: 52px`
- **预期效果**：提升 UI 精致度，确保触控区域达标，增强设计一致性

## 四、用户体验流程

### 问题 13：首次使用缺乏引导，新用户学习成本高

- **问题描述**：对于首次使用 SeedVR2 的用户，修复页的 20+ 个参数（尤其是高级参数中的 DiT 节点、VAE 节点、Upscaler 节点分组）缺乏直观的说明和引导。用户不知道哪些参数是关键的、默认值是否合适、不同模型大小的区别是什么。设置页的"内存策略"三个选项（均衡/性能/保守）也缺少清晰的适用场景说明。
- **所在位置**：修复页参数区、设置页
- **严重程度**：🔴 高
- **优化建议**：
  - 修复页添加入门引导浮层（Onboarding Tour），高亮 3-5 个核心操作
  - 每个关键参数添加 Tooltip 说明（悬停显示简要解释和推荐值）
  - 增加"新手/高级"模式切换，新手模式仅显示 5-6 个核心参数
  - 内存策略等设置补充适用场景说明文案
  - 参考实现：
    ```html
    <div class="sv-param-group">
      <label class="sv-param-label" for="ditModel">
        模型
        <i class="bi bi-question-circle sv-help-icon" data-tooltip="模型越大效果越好，但速度越慢、显存占用越高"></i>
      </label>
      ...
    </div>
    ```
- **预期效果**：新用户上手时间缩短 50%，参数配置错误率降低，用户满意度提升

### 问题 14：批量处理流程缺少预确认和预估信息

- **问题描述**：批量修复功能（[restore.html](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/templates/restore.html#L107-L143)）中，用户点击"从文件夹批量处理"后直接开始处理，缺少：
  1. 扫描后文件列表的预览和选择（用户无法排除不想处理的文件）
  2. 预估处理时间/显存占用
  3. 二次确认（批量操作是高成本操作，误启动代价高）

  这与"扫描 -> 选择 -> 确认 -> 执行"的标准批量处理流程不符。
- **所在位置**：修复页批量修复标签页
- **严重程度**：🔴 高
- **优化建议**：
  - 扫描后显示文件列表，支持勾选/取消勾选单个文件
  - 显示文件总数、预计总时长（基于单文件平均时长估算）
  - 开始批量前弹出确认框，展示文件数量和预计时长
  - 添加"全选/反选"快捷操作
- **预期效果**：降低误操作风险，提升用户对批量处理的掌控感和信任感

### 问题 15：错误提示缺乏行动指引，用户不知如何解决

- **问题描述**：当前的错误 Toast 仅显示错误信息（如"扫描失败: xxx"、"修复失败: xxx"），但缺少下一步行动建议。例如 GPU 不可用时，虽然有警告提示，但没有引导用户去检查驱动、确认 CUDA 安装等具体步骤。用户看到错误后仍不知道该怎么做。
- **所在位置**：全局错误提示
- **严重程度**：🟡 中
- **优化建议**：
  - 重要错误增加"查看帮助"或"如何解决"链接
  - 错误消息格式从"发生了什么"升级为"发生了什么 + 你可以怎么做"
  - GPU 相关错误提供诊断建议（检查驱动、确认 CUDA、查看日志等）
  - 示例：
    ```javascript
    // 优化前
    SeedVR2.toast('修复失败: ' + err.message, 'error');
    
    // 优化后
    SeedVR2.toast({
      type: 'error',
      title: '修复失败',
      message: err.message,
      action: { text: '查看常见问题', onClick: () => openHelp('restore-failed') }
    });
    ```
- **预期效果**：用户自助解决问题比例提升，减少技术支持成本

## 五、视觉舒适度与感知分析（重点）

### 问题 16：浅色模式纸张颗粒纹理增加阅读疲劳

- **问题描述**：[style.css](file:///c:/Users/HONOR/Seedvr2/bin/integrated_app/static/css/style.css#L252-L254) 浅色主题的纸张颗粒不透明度为 0.02，混合模式为 `multiply`。虽然数值看起来很小，但在大面积白色背景上，颗粒纹理会让纯白背景变得"脏脏的"，长时间阅读文字时眼睛需要更用力聚焦，增加视觉疲劳。尤其在高 DPI 屏幕上，噪点效果更明显。
- **所在位置**：浅色模式全局背景
- **不舒服的感觉**：就像在一张质量不太好的复印纸上阅读，纸面上有细细的颗粒感，字不够"干净"，看久了眼睛发涩。
- **严重程度**：🟡 中
- **优化建议**：
  - 将浅色模式的颗粒不透明度降至 0.008-0.01
  - 或仅在 Hero、卡片等特定区域应用纹理，而非全局覆盖
  - 增加纹理大小（从 200px 增加到 400px），降低颗粒密度
  - 提供开关设置，允许用户关闭纸张纹理
- **预期效果**：长时间使用视觉疲劳降低 20-30%，文字阅读更清爽

### 问题 17：多处发光阴影效果叠加，视觉显得"油腻"

- **问题描述**：设计中大量使用 `box-shadow: var(--sv-shadow-glow)` 发光效果：品牌图标、按钮激活态、卡片 hover、上传区 hover、进度条完成态、开关等都有发光效果。过多的发光阴影叠加后，界面整体有一种"朦胧感"或"油腻感"，降低了精致度，给人一种"廉价的霓虹灯"印象。
- **所在位置**：全局交互元素
- **不舒服的感觉**：就像整张图都加了一层柔光滤镜，边缘不够锐利，细节糊在一起，有种"雾蒙蒙"的廉价感。
- **严重程度**：🟡 中
- **优化建议**：
  - 建立发光阴影的使用规范：仅用于 CTA 按钮、关键状态指示
  - 次级交互元素（如 nav-icon-btn hover）移除发光效果，改用边框色变化
  - 降低发光强度：`--sv-primary-glow` 透明度从 0.28 降至 0.15
  - 减少使用发光的组件数量，保留品牌 logo、主按钮、成功状态等关键触点
- **预期效果**：界面更清爽精致，减少视觉噪点，提升高端感

### 问题 18：字体大小分级不够清晰，正文与辅助文字区分度不足

- **问题描述**：正文字号 15px，辅助文字 0.8rem（约 12.8px），说明文字 0.75rem（约 12px），眉标 0.7rem（约 11.2px）。小字号之间差异太小（12.8 vs 12 vs 11.2），视觉上几乎无法区分层级，导致信息层次扁平，用户扫视页面时难以快速区分主次。
- **所在位置**：全局文字排版
- **严重程度**：🟢 低
- **优化建议**：
  - 建立更清晰的字号阶梯：正文 15px、辅助 13px（0.8125rem）、说明 12px（0.75rem）、标签 11px（0.6875rem）
  - 眉标（eyebrow）字重从 500 提升到 600，增加字重区分
  - 确保每级字号差异 >= 2px，形成清晰的视觉阶梯
  - 参考 Modular Scale 比例（1.2 或 1.25）
- **预期效果**：信息层次更清晰，扫视效率提升，整体排版更专业

### 问题 19：毛玻璃效果与纸张纹理叠加产生"雾感"

- **问题描述**：导航栏、Toast、模态框等组件使用了 `backdrop-filter: blur()` 毛玻璃效果，同时全局覆盖着纸张颗粒纹理。两者叠加后，毛玻璃区域的纹理被模糊处理，产生一种"隔着脏玻璃看东西"的雾感，界面不够通透。
- **所在位置**：导航栏、Toast 通知、模态框等毛玻璃组件
- **不舒服的感觉**：就像透过一层起雾的窗户看外面，景物轮廓模糊，颜色发灰，不够透亮。
- **严重程度**：🟢 低
- **优化建议**：
  - 在毛玻璃元素上禁用纸张纹理（使用 `background: var(--sv-bg-base)` 覆盖）
  - 或降低毛玻璃的模糊半径（从 12px 降至 8px）
  - 增加毛玻璃背景的不透明度，减少纹理透出
- **预期效果**：界面更通透干净，提升精致度

### 问题 20：主题切换缺少过渡动画，明暗切换生硬

- **问题描述**：主题切换（明/暗模式）时，所有颜色瞬间变化，没有过渡动画。在深色环境下切换到浅色模式时，屏幕突然变亮会产生刺眼感；反之亦然。这种"硬切"的体验不符合 Warm Print 优雅柔和的品牌调性。
- **所在位置**：全局主题切换
- **不舒服的感觉**：就像在黑暗中突然打开强光，或者在明亮处突然关灯，眼睛需要时间适应，有一瞬间的不适感。
- **严重程度**：🟢 低
- **优化建议**：
  - 添加颜色过渡动画：`transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease`
  - 或使用 CSS `@property` 实现自定义属性的平滑过渡
  - 过渡时长控制在 250-350ms，配合 ease-out 缓动
- **预期效果**：主题切换更柔和自然，减少视觉冲击，提升高级感
